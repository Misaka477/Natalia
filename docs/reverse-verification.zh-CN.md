# 反向检验：让"已验证"有代价支撑

> 测试全绿只证明代码符合测试的断言，不证明测试断言了任何东西。本文是查明属于
> 哪一种的规程，以及守卫失效的五种形状。

对每一个"X 已验证"的宣称，在相信它之前这样做：

1. **说出属性。** 一句话：该宣称成立必须什么是真的。
2. **破坏它。** 改产品代码让该属性为假。改动要小，且正对该属性——不是重构，
   不是另一个 bug。
3. **跑那些声称守住它的测试。**
4. **转红或一无所踪。** 有测试转红，守卫有牙，宣称成立。若全都保持绿色，
   守卫并没有守那个属性——记录它属于下面五种形状中的哪一种，然后修那个，
   不是修产品。

写下任何东西之前先还原变异。`git diff --stat` 是判断文件是否还原的权威——
数字符串出现次数不是，因为同一字符串可能合法地出现在文件别处（实测：一次超时
杀掉了还原步骤，而一处 `?? 0` 残留经查明是文件里本来就有的三处用法）。

## 守卫失效的五种形状

五种都是同一次会话里这样发现的。列出来是因为**认出形状就完成了大半工作**——
修法随之而定。

### 1. 恒真

检查把实现和自己比较。

```ts
// 两边都来自被检模块，永远不可能不一致。
JSON.stringify(spec.env) === JSON.stringify({ ...ENV_OVERRIDES });
```

> **这一段是历史形态，仓库里已不存在。** 它在 `scripts/verify-pwsh.ts`，发现后当天改成
> 钉字面值（同文件 55 行附近的注释记录了此事）。列在这里是因为这个**形状**仍会复发，
> 不是因为可以照这段 grep 到它。
>
> **逐形状的当前状态**（这句是审计过的，不是写时的印象）：
>
> | 形状                 | 状态                                                                                                                                   |
> | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
> | 1 恒真               | 已修（本文即其记录）                                                                                                                   |
> | 2 被测物与运行物的缝 | **仍活跃**——`chat-compaction-streams.test.ts` 仍自建 `new ContextLedger()`，工厂缝已有测试钉住，但"测试练构造、生产走工厂"这个模式还在 |
> | 3 属性对、文件错     | **仍活跃**——`system-prompt-assembly.test.ts` 仍在读源码文本；`945f85ba` 只是补了一条断言，没移除它                                     |
> | 4 断言弱一档         | **已修**——`cff49387` 补了 `not.toMatch(/^([A-Za-z]:)?[\\/]/)`                                                                          |
> | 5 宣称比测试大       | **宣称已修**（`a5721184` 改名），底层缺口（记录契约 ≠ 应用启动）已写在测试注释里                                                       |
>
> 坐标用 commit SHA，不用轮次——轮次只对写这份文档的那次会话有意义，读者无法据它
> 验证；SHA 可以 `git show`。这正是本文在防的那类坐标。
>
> 只有 2 和 3 是"当前仍可去做变异"的活靶子。把已修与未修混在一起，会让读者去 grep
> 一个已经不存在的问题——这正是本文要防的那类事。
>
> **而"活靶子"本身也会过时。** 2 和 3 现在可抓，**是因为 `86031ca8` / `945f85ba` 恰好给它们补了
> 钉子**（工厂同目录断言、组装点字节一致断言）。本文写就时重新验证过两者：
> 破坏属性 → 那两条新断言转红。但那是"写就时"为真，不是永久为真——
> 哪天有人删了那些钉子，这句话就和形状 1 一样变成幽灵。
>
> 所以这句承诺的保质期，取决于它指向的测试是否还在。**读者照此表动手前，先自己变异一次。**

实测：从 executor 里删掉 `PAGER`，检查保持全绿。**一个不可能失败的检查比没有
检查更糟**——它报告了不存在的覆盖。

### 2. 被测物与运行物之间有缝

测试练的是构造函数或辅助函数，生产走的是工厂或组装点。

```ts
// 测试：两个实例互相独立。
const naviLedger = new ContextLedger();
const niaLedger = new ContextLedger();
// 生产，无人看守：
create: () => shared;
```

实测：让工厂返回同一个共享 ledger，没有任何测试转红——而那会让两个 agent 共用
一份压缩状态。

### 3. 属性对，文件错

断言把源码当文本读，而属性活在组装它的代码里。往静态 prompt 上拼一个
`Date.now()` 破坏了属性，却一个断言都没碰到。

### 4. 断言比属性弱一档

这是最难发现的一种，因为它读起来完全像那个属性：

```ts
// 属性：渲染出的 Source 路径是相对的。
// 断言：它不含"本次运行"的 release 目录。
expect(line).not.toContain(release);
```

**另一台机器**的绝对路径能通过。实测：烤入 `/home/buildmachine/…`，那条名为
"Source paths are release-relative" 的测试保持全绿。

### 5. 测试是对的，宣称比测试大

一个 portable bundle 测试真解压真 tarball、真执行入口点——那确实是打包器的全部
职责。但它的名字说"starts the application"。**没有任何东西坏了，坏的是承诺。**

这就是"已验证"悄悄变得比背后证据更强的机制，而它是唯一一种**再怎么写测试都修不了**
的形状。

## 两条操作判据（比五种形状更常用）

五种形状讲的是**测试可能怎么骗你**。这里两条讲的是**你可能怎么骗自己**——同一个会话里，
它们的出现频率高于五种形状加总。

### 一、不确定刚才那下成功了吗？去看 `git diff --stat`

不是回忆你做了什么，不是看那条命令有没有报错。

同一个会话里这个错误犯了两次，两次都是"命令没报错"掩护的：

- 一次 `git checkout --` 落在含未提交工作的文件上，改动被静默清掉
- 一次 python 替换 assert 失败没写盘，我却以为改好了，接着据"已改好"往下推

**判据只有 `git diff --stat`。** 空 = 干净；非空 = 看清楚多出来的是什么再决定下一步。

### 二、每句"已验证"都要能回答"你验了什么"

包括这句本身。

"本地无法复现"是最常见的伪装——说的时候觉得自己试过了。同一个会话里，它让我把 CI 失败当归析，
六轮之后才发现**我从未用 CI 的真实形状跑过**（只单文件跑过 5 次）。一换成 CI 的并发形状就复现了。

**一条宣称成立，必须能指出具体的那个动作。** 说不出动作的，写成"我认为"而不是"我验过"。
这两者在纸面上差一个词，在后续十轮里差一次空转。

## 它给不了你什么

没有自动版。五种形状没有共同的机械特征——一个是自我比较，两个跨模块，一个是弱断言，
一个是措辞。一个声称能检出全部的守卫，本身就是形状 1 的实例。

能通用的是**规程**，所以它是一份文档而不是 lint 规则：破坏属性、观察守卫，并把
"全绿"当作一个发现而非一次通过。

## 何时停手

守卫可能确实无法验证某个属性，而诚实的回应是**记录这件事**，而不是把断言加强成演戏。
桌面托盘随窗口销毁（`delete tray_`）由**字符串包含**检查钉住，因为行为级验证需要
编译好的 CEF 二进制和一个显示器，而写它的主机两者都没有。测试文件在读者会看到的
位置写明了这一点。**那是当下可得的正确结果，不是一个更聪明的正则。**
