# 反向检验：让"已验证"有代价支撑

> 测试全绿只证明代码符合测试的断言，不证明测试断言了任何东西。本文是查明属于
> 哪一种的规程，以及守卫失效的五种形状。

对每一个"X 已验证"的宣称，在相信它之前这样做：

1. **说出属性。** 一句话：该宣称成立必须什么是真的。
2. **破坏它。** 改产品代码让该属性为假。改动要小，且正对该属性——不是重构，
   不是另一个 bug。
3. **跑那些声称守住它的测试。**
4. **转红或一无所踪。** 有测试转红，守卫有牙，宣称成立。若全都保持绿色，
   守卫并没有守那个属性——记录它属于下面五种形状中的哪一种，然后修那个，
   不是修产品。

写下任何东西之前先还原变异。`git diff --stat` 是判断文件是否还原的权威——
数字符串出现次数不是，因为同一字符串可能合法地出现在文件别处（实测：一次超时
杀掉了还原步骤，而一处 `?? 0` 残留经查明是文件里本来就有的三处用法）。

## 守卫失效的五种形状

五种都是同一次会话里这样发现的。列出来是因为**认出形状就完成了大半工作**——
修法随之而定。

### 1. 恒真

检查把实现和自己比较。

```ts
// 两边都来自被检模块，永远不可能不一致。
JSON.stringify(spec.env) === JSON.stringify({ ...ENV_OVERRIDES });
```

实测：从 executor 里删掉 `PAGER`，检查保持全绿。**一个不可能失败的检查比没有
检查更糟**——它报告了不存在的覆盖。

### 2. 被测物与运行物之间有缝

测试练的是构造函数或辅助函数，生产走的是工厂或组装点。

```ts
// 测试：两个实例互相独立。
const naviLedger = new ContextLedger();
const niaLedger = new ContextLedger();
// 生产，无人看守：
create: () => shared;
```

实测：让工厂返回同一个共享 ledger，没有任何测试转红——而那会让两个 agent 共用
一份压缩状态。

### 3. 属性对，文件错

断言把源码当文本读，而属性活在组装它的代码里。往静态 prompt 上拼一个
`Date.now()` 破坏了属性，却一个断言都没碰到。

### 4. 断言比属性弱一档

这是最难发现的一种，因为它读起来完全像那个属性：

```ts
// 属性：渲染出的 Source 路径是相对的。
// 断言：它不含"本次运行"的 release 目录。
expect(line).not.toContain(release);
```

**另一台机器**的绝对路径能通过。实测：烤入 `/home/buildmachine/…`，那条名为
"Source paths are release-relative" 的测试保持全绿。

### 5. 测试是对的，宣称比测试大

一个 portable bundle 测试真解压真 tarball、真执行入口点——那确实是打包器的全部
职责。但它的名字说"starts the application"。**没有任何东西坏了，坏的是承诺。**

这就是"已验证"悄悄变得比背后证据更强的机制，而它是唯一一种**再怎么写测试都修不了**
的形状。

## 它给不了你什么

没有自动版。五种形状没有共同的机械特征——一个是自我比较，两个跨模块，一个是弱断言，
一个是措辞。一个声称能检出全部的守卫，本身就是形状 1 的实例。

能通用的是**规程**，所以它是一份文档而不是 lint 规则：破坏属性、观察守卫，并把
"全绿"当作一个发现而非一次通过。

## 何时停手

守卫可能确实无法验证某个属性，而诚实的回应是**记录这件事**，而不是把断言加强成演戏。
桌面托盘随窗口销毁（`delete tray_`）由**字符串包含**检查钉住，因为行为级验证需要
编译好的 CEF 二进制和一个显示器，而写它的主机两者都没有。测试文件在读者会看到的
位置写明了这一点。**那是当下可得的正确结果，不是一个更聪明的正则。**
